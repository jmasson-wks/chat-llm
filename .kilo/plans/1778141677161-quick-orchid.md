# Plan : préfixer `BASE_PATH` sur les `<a href>` internes

## Problème

Sous déploiement sous-chemin (`BASE_PATH=/ia`), certains liens de la barre latérale
(threads, workspaces) se rendent en `<a href="/workspace/nautilus/t/...">` sans le
préfixe `/ia`. Cliquer sur ces liens sort du sous-chemin et casse la navigation
IIS (404 ou recharge à la racine du domaine).

## Cause racine

Le commentaire en tête de `frontend/src/utils/paths.js:9-17` affirme que React
Router pré-préfixe automatiquement le `basename`. C'est vrai pour
`<Link to>` / `useNavigate`, **mais pas pour les balises `<a href>` standard** :
celles-ci écrivent directement dans la barre d'URL, comme
`window.location.href`.

Le patch initial `[base-path]` enveloppait correctement chaque
`window.location.* = paths.xxx()` avec `withBase()`, mais a oublié les
nombreux `<a href={paths.xxx()}>` du code. Ce sont eux qui produisent les
liens cassés visibles dans la capture HTML fournie.

Élément déclencheur dans la capture utilisateur :

- `frontend/src/components/Sidebar/ActiveWorkspaces/ThreadContainer/ThreadItem/index.jsx:99-103`
  → `<a href={linkTo}>` où `linkTo` vaut `paths.workspace.thread(...)`.
- `frontend/src/components/Sidebar/ActiveWorkspaces/index.jsx:120-125`
  → `<a href={paths.workspace.chat(workspace.slug)}>`.

## Stratégie

Envelopper avec `withBase()` chaque `<a href={paths.xxx()}>` qui cible une
route **interne** du SPA. `withBase()` :

- est idempotent (`paths.js:24-27`) ;
- laisse passer les URLs absolues / `mailto:` / `//` (`paths.js:22-23`) ;
- est un no-op quand `BASE_PATH` est vide.

Il est donc sûr d'appliquer `withBase()` même sur les hrefs externes ; pour
limiter la diff et rester lisible, on ne touche que les hrefs internes.

Marquer chaque modification d'un commentaire `// [base-path]` (convention déjà
en place) afin que `git grep "\[base-path\]"` continue à lister toutes les
divergences pour le rebase.

Ces callsites utilisent déjà des URLs absolues ou des protocoles non-http
(`mailto:`, `https://`, `tel:`). `withBase()` les laisserait passer tels quels,
donc on ne les touche pas pour minimiser la diff :

> Les fonctions retournant des chemins ne sont pas préfixées : React Router
> auto-préfixe `<Link>` / `useNavigate`. Les balises `<a href>` brutes
> **bypassent React Router** et doivent être enveloppées de `withBase()`,

## Tests de fumée

1. `BASE_PATH` vide → vérifier que les hrefs sont inchangés (no-op de `withBase`).
2. `BASE_PATH=/ia` (déploiement Docker actuel) :
   - Inspecter la barre latérale : chaque `<a>` thread/workspace doit afficher
     `href="/ia/workspace/..."`.
   - Cliquer sur un thread → URL bar reste sous `/ia/...`, pas de 404 IIS.
   - Cliquer sur les liens de la `SettingsSidebar` (Agent skills, Security,
     Beta features) → idem.
   - Cliquer sur un lien de `WorkspaceRow` admin → idem.
3. Vérifier qu'aucun href ne devient `/ia/ia/...` (idempotence de `withBase`).
4. `git grep "\[base-path\]"` doit toujours lister toutes les divergences,
   y compris les nouvelles.

## Hors scope

- Les `<Link to>` / `useNavigate` restent intacts (React Router gère).
- Pas de refactoring de `paths.js` pour pré-préfixer globalement : cela
  casserait React Router (double préfixe documenté lignes 9-13).
- Pas de PR upstream (cf. section « Upstream-friendliness » de
  `vendor-dependencies.md`).
